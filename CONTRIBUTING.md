# Contribuicao

Obrigado por contribuir com o SecPolicy HAMA.

## Fluxo recomendado

1. Crie uma branch a partir de `main`.
2. Implemente a alteracao com escopo claro.
3. Rode `npm run lint` e `npm run build` antes de abrir PR.
4. Abra PR com descricao objetiva, riscos e plano de teste.

## Convencoes

- mantenha TypeScript estrito e sem `any` desnecessario;
- preserve o fluxo principal (checklist -> score -> PDF);
- evite mudancas visuais sem justificativa funcional;
- adicione/atualize documentacao quando houver mudanca de produto.

## Issues

- roadmap: melhorias planejadas;
- demo/comercial: interesse de adocao;
- bug: defeitos reproduziveis com passos claros.

## PR checklist

- [ ] Escopo da mudanca definido
- [ ] Impacto no fluxo principal validado
- [ ] Lint/build executados
- [ ] Documentacao atualizada
