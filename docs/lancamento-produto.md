# Lancamento do produto no GitHub

Este checklist operacional ajuda a transformar o repositório em canal de venda.

## 1. Posicionamento publico

- [ ] Revisar tagline e proposta de valor no README.
- [ ] Garantir screenshots atualizadas do fluxo principal.
- [ ] Validar CTA para solicitacao de demo/proposta.

## 2. Estrutura comercial

- [ ] Definir preco-base por pacote (Starter, Pro, Enterprise).
- [ ] Definir prazo padrao de implantacao por pacote.
- [ ] Definir escopo fechado do MVP comercial.

## 3. Publicacao da versao

- [ ] Rodar validacoes locais (`npm run lint`, `npm run build`).
- [ ] Criar tag semantica (ex.: `v0.1.0`).
- [ ] Publicar release com notas objetivas e limitacoes conhecidas.

## 4. Captura e qualificacao de demanda

- [ ] Monitorar issues com label `demo` diariamente.
- [ ] Responder em ate 1 dia util com roteiro de discovery.
- [ ] Converter demanda qualificada em proposta tecnico-comercial.

## 5. Rotina de melhoria continua

- [ ] Revisar roadmap mensalmente.
- [ ] Priorizar funcionalidades que reduzem tempo operacional do cliente.
- [ ] Registrar cases e resultados para prova social.

## Modelo de release notes (v0.1.0)

Titulo sugerido:

`v0.1.0 - MVP comercial do SecPolicy HAMA`

Resumo sugerido:

- Fluxo principal operacional: checklist -> score -> PDF.
- Persistencia e historico de registros.
- Estrutura comercial inicial no repositorio (oferta e demo).
- Roadmap publico para evolucao de produto.
